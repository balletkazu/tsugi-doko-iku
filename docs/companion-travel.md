# おとも旅と旅の手帖

## プレビューでできること

街の郵便から募集の下書きを作れる。出発日、大まかな行き先、メモ、公開範囲の希望を入力し、自分の広場にある「おとも募集」で見返す。実際に共有される範囲はこの端末。街の架空の住人に自分のおともを送り、日付ごとに最大3人ずつの絵はがき、コイン、ありがとうの記録を見返せる。募集への参加、オート同行設定、歩数は端末内試遊。出発日を迎えた下書きは、架空の住人を連れるホスト側の操作も試せる。おとも参加の記録は現実に訪問した実績とは区別する。

ショップの通常・レアは固定のコイン価格。所持品を模様替え・着替えから使える。記録した旅と歩数目標の達成で期限なしのコインが増える。Webの歩数は自己申告。現実の旅の報酬は日本の日付・体験種別ごと、歩数は記録日ごとに一度。利用しなかった日の減点、連続ログイン、ランキング、期限付きの景品は設けない。

## 共有サービスへの接続の設計

`database/003_companion_travel.sql` は既存のアカウント、投稿、ミュート、ブロック、通報のマイグレーションに続けて適用する。募集は初期値を非公開・審査待ちとし、自分、相互の友達、ログイン済みの一般利用者、審査待ちをアクセス制御で区別する。募集には日付と地域名を使い、緯度経度や現地のリアルタイム位置を持たない。住所、連絡先などが投稿本文に書かれた場合に審査できるよう、公開前にサーバーでレビューする。

世界に表示する本体キャラクターと、同行の席に登録する姿を別に扱う。利用者は複数の旅へ同時におともを送れる。無料／有料の暫定上限は日本時間の日付ごとに5／10件、自分の募集の定員は20／30人。友達のレコードは上限を持たない。同行時には対象の旅と参加者の行をロックし、両方の上限を同じ処理で検査する。自動同行は本人の許可・相互の友達を条件に、サーバーの作業用アカウントから予約する。ミュートとブロックを予約時にも確認する。

利用者が閉じている間でも、おともの予約と報酬はバックエンドで扱う。ホストが旅を完了しサービス側で承認した後に、予約者への受領記録とホストへのコインを確定する。受領記録は旅と受取人の組で重複を防ぐ。有効期限は持たせない。初期版は3人単位のグループ番号を振る。レンダリングのジョブは承認済み背景と本人許諾済みのキャラクターだけを合成し、出力は非公開の画像バケットへ保存する。閲覧時にアクセス権を再評価し、短期限の署名URLで配信する。保存済みの権利はURLの期限とは独立させる。画像管理表はサービスロールのみ操作できる。DBテストは読者、別グループ、ブロック後のアクセス再判定を含む。ホストの写真への正確なGPS埋め込みを防ぐため、アップロード側も再エンコードとメタデータの検査を行う。

購入は商品ID、価格、通貨、提供対象を分ける。現在は端末内のコイン台帳だけを更新する。将来の直接購入は決済側の確定済み取引IDを重複防止に使い、同意済みの販売条件・プラットフォーム規約・返金の扱いを確認して有効にする。現在の配信で有料の決済やガチャを起動する経路はない。

## 検証と残り

ローカルPostgreSQL互換環境の試験 `tests/companions.db.mjs` で、複数アカウントの公開範囲、相互の友達、明示許可、ミュート・ブロック・通報、定員、上限、重複防止と受領記録の読取を確認する。認証・DB・画像バケット・常駐ジョブをPreviewに接続した後は、実端末間での一連の流れ、複数同時リクエスト、取消し・同意撤回、公開設定変更、通報の対応と期限なしの受取を検証する。招待・静止画・スタンプなどの機能を同じサービスに繋いだ時の公開範囲はRLSと審査済み配信の両方で強制する。接続にはオーナー管理のプロジェクト設定が必要で、手順は [DBの設定案](community-database.md) にある。
