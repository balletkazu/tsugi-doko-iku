# 利用者どうしの交流に向けたデータベース

[初期マイグレーション](../database/001_community.sql) にプロフィール、投稿、写真の順序・表紙、フォロー、リアクション、ブロック、限定公開の閲覧者を定義した。Supabase の PostgreSQL と Auth を候補とする。写真は投稿内の枠1〜10を使い、表紙を複数登録できない。投稿の既定は非公開。権限を持たない利用者が公開状態・審査結果を書き換えられないようにし、投稿と写真の閲覧は同じ権限で判定する。運営用の公開処理、ストレージ、Web アプリとの接続は次の工程。

## 次の工程とオーナーにお願いすること

1. 無料の Supabase プロジェクトを作成または選択し、このアプリへの接続と、プレビュー環境だけでの利用を承認する。組織やリージョンは利用者情報を保管する場所として確認する。契約前に無料枠、ストレージ、配信量、メール認証の制限を確認し、有料化が必要な場合は別途相談する。
2. 接続時は Project URL と Publishable key を Vercel の `Preview` 環境向けに設定する。シークレットキー、DB パスワード、管理用トークンはチャットや GitHub に貼り付けない。マイグレーションの実行権限は別途確認する。共有版のバックエンドが必要とする設定は接続着手時に追加する。
3. 招待したテスト利用者で、非公開、招待者、一般公開、ブロックの組み合わせを検証する。写真用の非公開バケット、署名付きアクセス、アップロード検査、利用枠、投稿・写真の削除を実装する。公開する前にモデレーション、ミュートと通報、退会とデータ削除を揃える。匿名アクセスやエラー経路から非公開の日記や写真が出ないこと、期限切れの共有リンクが開かないことを確認する。
