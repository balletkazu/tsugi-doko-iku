# 現実の旅を持ち帰るRPG

## 試遊する

1. 実写をタップするか、約2.5秒待つ。初回の案内で旅人の名前と姿を決める。
2. 家の床をタップして歩き、旅地図を開く。行き先を選んで散策し、仮想の旅印を受け取る。チュートリアルは飛ばせる。家から何度でも再確認できる。
3. 街では住人に話しかけたり、施設名をタップしたりできる。広場には編集部のサンプル、駅には実ダイヤを使った富山市の経路検索がある。
4. 現実の体験は「体験を記録」で手入力するか、測位を自分で開始する。候補を直し、必要なら場所・都道府県・写真を添えて「自分の体験として記録」を押す。
5. 絵日記から写真と旅人の絵はがきをPNGで書き出すか、絵入りの栞を作って編集・印刷する。家では記念品を3か所へ配置し、写真を壁に飾れる。鏡で記念品のバッジを身につけられる。

## 今回の実装とデータ

- 人物は名前と11項目の組み合わせ。12種類の動作、家での自発的な行動、手動移動に対応。持ち物は体験の種類に応じて増え、訪問回数の競争は設けない。
- 街の入口は広場、駅、旅行案内所、図書館、美術館、郵便局、博物館、アトリエ。メニューからも直接開ける。既存のサンプル投稿、写真最大10枚の下書き、栞・日記、スタンプ帳を継承する。
- 47都道府県を選ぶ絵地図には Natural Earth 地形と概略地点を使用。地方と季節をもとにした4景は創作で、各県の名所の写実的な再現ではない。実用地図を選ぶと国土地理院の淡色タイルを読み込み、ドラッグと拡大縮小が使える。地図サイトに送るのは表示した範囲のタイル番号。測位とタイルの読み込みは独立している。
- 行動連動はHTTPSの前面画面で、利用者の操作から最大60秒。速度・測位誤差・時刻差・標高差を用い、十分に近い掲載施設名は参考情報として出す。加速度は別の操作で許可した場合に揺れの目安を表示する。乗り物の種類、天候、宿泊等は本人が手入力できる。速度だけで電車・バスなどを断定しない。測位値、センサーの時系列は永続化しない。非表示、画面移動、手動停止で監視を解除する。
- 確定した体験の種類、任意の地名・都道府県・写真、保存時刻、当時の旅人の姿をIndexedDBに保存。都道府県は本人申告の訪問としてスタンプ帳に反映。写真はJPEGに再生成し、絵日記は圧縮後の写真合計24MiBまで。仮想の散策は別配列。実体験・元写真のサーバー送信、公開、アカウント間同期は行わない。絵日記から作成した栞や端末へ書き出した画像は独立したコピーとなる。
- 旅人の鏡は端末内のルール式。回答と、個別に許可された保存先のテーマ・本人が記録した体験の種類だけで候補を更新する。私的な日記本文を分析対象にしない。外部AIによる推論は未接続。
- 富山の765便は公式 shapes.txt と停車順を照合。経路検索の乗車区間だけを切り出して実用地図に描く。歩行線形は宝町から富山駅への片方向を検証した。その他の徒歩区間では道路上の経路と誤認されないよう両端だけを示す。合計徒歩上限は0〜180分、1分刻みで、30・60・120分のボタンを用意する。候補内の既知運賃順を選べる。降車地点からチェック済み周辺2地点へ徒歩往復30分以内で、旅全体の徒歩上限にも収まる場合に寄り道を示す。滞在後の接続は要再検索。背景タイルはオンラインで都度取得。時刻表と絵地図は端末内で開ける。
- 編集部サンプルの反応に「すごい」「美味しそう」を追加。試遊用ミュート・ブロックはこの端末に効く。複数利用者向けには既存SQLに加え、002のマイグレーションでミュートを反映するフィード、初期閉鎖のコメント、本人向け／読者向けの公開範囲、審査、通報者本人に限定した通報履歴を用意。公開後の設定変更、通報の処理、再審査は信頼されたバックエンドで行う。広場や案内役を実在利用者と表示しない。

## 描画、保存、外部サービス

Canvas 2D とHTMLの組み合わせを採用。背景・輪郭・動作規則は[作画帳と素材台帳](rpg-art.md)に記載。WebGLを必要とせず、操作はフォームやリンクでも行える。人物の更新は表示中に約2.4回/秒、非表示時は描画を休止し、画面を離れるとタイマーを破棄する。「音と動き」とOSの動きを減らす設定を尊重する。ゲームの保存先は既存DBの新しいキーで、旧来の栞・日記・写真を引き継ぐ。

地理院タイルをリアルタイムに読み込む場合は出典と一覧へのリンクを表示する。端末への一括取り込みは行わない。MapLibre GL JS（BSD-3-Clause）は広域ベクター地図や多数のレイヤーが必要になった時に再評価する。PixiJS（MIT等、導入版のライセンスを再確認）は多数の動体を同時に扱う場合の候補。ネイティブ化では保存モデルと推定処理を再利用し、OSの位置許可、バックグラウンド中の通知・省電力・削除操作を別途実装する。今回の試遊に新規登録・有料API・APIキーは不要。

## 次の段階

1. iPhone Safari・Android実機で、位置情報を許可／拒否した時、機種別の加速度・標高、写真書き出し、低メモリ時の復帰を確認。閉じている間の追跡を希望する場合は、用途を提示して個別同意するネイティブ試験を用意する。
2. 関西の対象路線を選定。ライセンスと運行期間を確認した事業者から追加し、船、通学・観光便、乗降ルール、運賃・運休・乗り継ぎを検証する。通過時刻だけから経路を生成しない。徒歩線形、風景・経路上の寄り道、格安経路は地域ごとの裏付けを得て広げる。
3. アカウント・認証用のステージング、画像の非公開ストレージ、投稿・コメント・通報の審査画面、ブロック、削除・同意撤回と費用上限を結合試験する。Supabaseを採用する場合のユーザー側の操作は[DBの設定手順](community-database.md)を参照。無料枠も含めて外部プロジェクトの作成は事前に相談する。貢献の通知は受け手から投稿者本人に返し、順位表は作らない。
4. 国立公園、世界遺産、百名山、ジオパーク、エコパーク、神社仏閣、温泉、地域文化、食・乗り物のコレクションを権利確認済みの一覧と図案で拡充する。実在施設・地域固有の風景、家の自由配置、装具の種類、旅の嗜好の説明と明示的なAI同意を段階的に追加する。

## 検証を再現する

`npm test`で20件を実行する。追加のブラウザー回帰試験は、PlaywrightとChromiumがある開発環境で、ビルド後に `node tests/world.browser.mjs` を実行する。Playwrightを別環境に入れた場合は `PLAYWRIGHT_MODULE` にモジュールの絶対パス、システムのChromiumを使う場合は `CHROMIUM_PATH` に実行ファイルを設定する。既存のディレクトリを `ARTIFACT_DIR` で指定すると画面を保存する。

320・390・768・1280pxで横はみ出しと導線を確認した。タッチでの初回案内、案内役、身支度、四季の散策、写真の読み込み、自宅の飾り、記念品の着用、絵はがきと栞、訪問と仮想散策の分離、オフライン再起動を通した。位置情報の許可・拒否・候補の修正・監視停止には模擬センサーを使用。地図UIの回帰試験は固定のタイル応答を使い、実際の国土地理院の配信先は別途PNGの取得を確認した。SQLのアクセス権はPGliteの2利用者で確認した。物理端末での測位精度や長時間移動の精度は未検証。
